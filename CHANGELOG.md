# Changelog

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 0.1.7

0.1.6 is still the newest version on the registry, and this section covers everything in the working tree since it. Two waves landed here: the delivery machinery around the package (workflow files, README, catalog floor — the first twelve entries below), and a review round that touched the library and the baseline configs themselves. `exports` is unchanged — no subpath was added, removed or renamed — but `lib/` and `config/` are not byte-identical to 0.1.6, so consumers that read fields on hostile objects, call `claimApply` flags, or lean on the vitest/oxlint baselines should read the entries below before moving. The eight consumers in this family were updated in the same round and their full checks pass against this tree.

### Changed

- **Every third-party action in the four workflow files is pinned to a commit SHA** with the resolved version in the trailing comment (`actions/checkout`, `pnpm/action-setup`, `actions/setup-node`, `actions/upload-artifact`, `actions/download-artifact`, `actions/attest`, `actions/dependency-review-action`, `github/codeql-action`, `ossf/scorecard-action`). A tag can be moved by its owner; a workflow whose only job is to judge whether a change is safe must not itself be re-pointable. `actionlint` no longer comes from a mutable container tag either — the CI step downloads the upstream release tarball, checks it against a pinned SHA-256, and only then runs it.
- **Concurrency groups carry the event name** (`${{ github.workflow }}-${{ github.event_name }}-${{ github.ref }}`), and cancellation is limited to `push` and `pull_request`. The weekly drift run and a push to `main` share `refs/heads/main`; grouping by ref alone let a push cancel the weekly run, which is the only signal for "did the host line move". The comment above the block in both `ci.yml` and `codeql.yml` records this.
- **The coverage upload runs under `if: always()`.** Uploading only on success meant the one artifact worth reading — the report from the run that failed — was the one never published. `if-no-files-found` is `warn`, not `error`: under `always()` the directory is absent whenever typecheck, lint or build fails first, and failing here would report a missing path over the real error and abort the remaining steps.
- **The run summary is the last step of the gate job.** `${{ job.status }}` is evaluated when that step runs, so any judging step after it left the summary asserting `success` while the job went on to fail — a single conclusion surface that is wrong rather than merely absent.
- **The build-provenance attestation is a separate job**, gated on `github.event_name != 'pull_request'`. `id-token` and `attestations` are job-level permissions: attaching them to the install job would hand a forked pull request the write capability regardless of any step-level `if`. The separate job declares `contents: read` + `id-token: write` + `attestations: write` + `artifact-metadata: write`, which is the full set the upstream action documents.
- **The install probe holds `contents: read` only.** It runs `pnpm pack` and `npm install`, which execute `prepack` and dependency install scripts from the pull request's own tree; a token reachable from that tree is a token an installer script can read.
- **Every `actions/checkout` passes `persist-credentials: false`.** Nothing in these workflows runs a git write verb, while the steps after the checkout do run the repository's own install, build and test scripts — leaving the token in `.git/config` widened what those scripts could reach for no benefit.
- **The publish workflow never lets its npm credential leave the step that reads it.** The secret is masked with `::add-mask::` and used in place by each of the two steps that need it — the registry pre-check and the publish step — rather than being handed on through a step output. A step output is materialised as a file under the runner's temporary directory, and every later step in the same job can enumerate and read it, which leaves the reachability problem that the job environment had: `pnpm install --frozen-lockfile` and `pnpm run check` run code from the repository and its dependencies. What crosses steps now is one boolean — whether the pre-check found a usable static token. The publish step exports `NODE_AUTH_TOKEN` only when that boolean is true and the value is non-empty: exporting an empty string would fill the `${NODE_AUTH_TOKEN}` placeholder that `setup-node` writes into the npm config with nothing, so an OIDC-only run would go on to authenticate with an empty credential. The token check exits `0` when the secret is absent, so publishing over OIDC (the path the registry records as `GitHub Actions <npm-oidc-no-reply@github.com>`) is not blocked by it.
- **The publish job has `timeout-minutes: 45`** and keeps `concurrency: publish` with `cancel-in-progress: false`. Without the timeout a stuck install or check burns the runner's default ceiling with no signal; without the concurrency group two dispatches race on the same version.
- **`.github/dependabot.yml` no longer has an npm update block.** Catalog truth lives in the umbrella root, and every other literal version in this manifest is pinned by `pnpm-workspace.yaml`'s `overrides` — a Dependabot bump of those would be resolved back to the pinned value, so the pull request would merge without changing the installed tree. The action block stays, and its groups now cover `github/codeql-action*` and `ossf/scorecard-action*`, which the previous patterns missed.
- **New README section: the shared version floor** (`README.md` / `README.zh-CN.md`). A consumer profile can pin this package with a pnpm `overrides` entry; pinning it below the version that introduced a `./lib/...` subpath installs a copy without the names the consumer imports at run time, and the host then reports `N entries did not activate` with `does not provide an export named ...` — the package installs, never loads, and no per-repository CI run can see it. The section points readers at `exports` and this file before pinning.
- **`catalog` for `@jayyuen66/dsh-plugin-shared` moves `^0.1.5` → `^0.1.6`**, the newest version the registry actually has; the previous floor named a version below the current one.
- **`config/vitest.base.ts` splits coverage overrides out of `test`.** The trailing `...test` spread let a consumer that only wanted to change one `coverage` reporter replace the whole block — the four-way 100 % thresholds and the exclusion list included — with nothing failing anywhere. Coverage overrides now go through a dedicated `coverage` option merged key by key, and `thresholds` itself is merged key by key, so relaxing one metric cannot delete the other three; `test.coverage` is rejected at load with a message pointing at the new option. `coverage.include` comes only from `coverageInclude` — the override option's shape has no `include` key at all, so the measurement surface stays single-sourced. Test discovery widens to `test/**/*.{test,spec}.{ts,tsx,mts,cts}` (a pure superset; no current file in any consumer matches the added patterns), the coverage exclusion list gains `**/*.d.ts`, `**/test/**` and `**/node_modules/**`, and an empty or whitespace `coverageInclude` throws at load instead of silently measuring nothing while the thresholds stay green.
- **`config/oxlint.base.ts` narrows the sonarjs escape hatch and exports the vitest rule snapshot.** The hatch now only skips resolution when the caller's own plugin entry actually resolves sonarjs; previously any caller-supplied `jsPlugins` entry silenced the failure, which resurfaced later as oxlint's own `Plugin 'sonarjs' not found` with none of the actionable message. `VITEST_ALL_RULES` is exported and a consistency test compares it against `oxlint --rules` at the installed version, so an upstream rule addition or removal reddens the gate instead of silently widening what the off-list covers. The case/spec file patterns are single-sourced, and the note that claimed `no-await-in-loop` was relaxed for scripts is corrected — that rule is on for both sides.
- **`lib/canonicalize-region-paths.ts` gains an exact-prefix mode: `canonicalizeRegionPaths(code, pkgDir, cwd?)`.** With `cwd` the two strippable prefixes are computed as `rel(cwd, pkgDir)` and `rel(cwd, parent(pkgDir))` instead of guessed by segment name, so a package-internal directory that happens to share the parent directory's — or the package's — name is no longer folded away, and the result is the same bytes from any build directory. All twenty build call sites across the family pass `process.cwd()`. The two-argument form is unchanged. One shape has no lossless fix in a pure-string pass and is documented in the module header instead: a package-internal directory named after the package itself, built with cwd exactly the package's parent, produces canonical text that a re-run would strip once more. A shape guard also keeps multi-line template literals whose content happens to begin a line with `//#region ` out of rewriting scope.
- **`lib/card-apply.ts` claims with a per-call symbol and restores what was there before.** The placeholder under the flag key is a fresh symbol per claim; cleanup removes it only when the key still holds that token and restores the previous property descriptor (or deletes the own property when there was none). A late disposer from a previous context can therefore neither clear a newer instance's flag — which used to let a third apply re-mount — nor leave a stale `true` blocking the next one. Flags are validated at load: an empty string or an `Object.prototype` member name throws instead of silently disabling the guard.
- **`lib/record.ts` reads never throw, and `Object.prototype` is not a service.** `fieldOf` and `hasMethods` are the capability probes consumers run against values from `ctx.get(...)`; a hostile getter or Proxy trap now degrades to `undefined` instead of escaping the probe site — `hasMethods({}, ["toString"])` and friends return `false`. Methods on classes and intermediate prototypes are still recognized; only the members that live on `Object.prototype` itself are refused.
- **`lib/errors.ts` follows from that: `isSettingsConflict`'s try/catch was dead code and is gone** — the never-throw contract now lives in `fieldOf` and is stated there. `errorText` also stops treating an owned empty string as "read a message": it falls through to `String(error)`, same reason as the empty-`message` fallback below it.
- **`lib/text.ts` treats sub-code-unit budgets as no budget at all.** `0 < minChars < 1`, NaN and non-positive values return the empty string — the same answer as `truncateEnd(text, 0)` — instead of `slice(-0.5)`'s whole string, which was exactly the truncation this function exists to enforce.
- **`lib/lesson-bus.ts` no longer leaks an async `onFailure` rejection, and settling failures no longer recurse.** `report()` now catches a rejection thrown asynchronously by an `onFailure` handler; the failure-swallowing path used by cleanup keeps its own rejections to a log line instead of handing them back to `onFailure` — the failure came from the settling itself, so reporting it through the same channel would recurse.
- **`lib/card-diff.ts` compares by form semantics instead of `JSON.stringify`.** `null`, `undefined` and an absent key stay equal; objects compare key set plus every value, arrays length plus every element, and the leaves go through `Object.is` — so `NaN` equals `NaN`, `-0` does not equal `0`, and key order no longer decides equality.
- **`lib/project-key.ts` recognizes UNC share roots.** `\\server\share` — with or without the `\\?\` long-path prefix and the trailing backslash — is a root, not a two-segment relative path mis-bucketed as one.
- **`lib/job-outcome.ts` drains the `kill()` promise and records `exitCode: null` completions as 0.** The official handle's `kill` returns `Promise<boolean>`; a synchronous try/catch only caught the throwing form, so a rejected promise escaped to the process-level unhandledRejection counter from a cleanup arm. `jobOutcomeOf` also writes `exit code: 0` when a completed process reports no exit code, matching the host's own `processOutcome` reading; consumers that project `proc.exitCode` are unaffected.
- **`lib/jsonl.ts` eats the whole leading blank run after a half-split, CRLF included.** The old `slice(1)` removed a single `\n` and never matched a `\r\n`-leading remainder, so a split landing inside a blank run could re-emit it.
- **`build-host.mjs` exports `facets`, and a parity test now pins all four hand-maintained lists.** The barrel member list, the `dist/index.d.ts` facet list, the tsconfig include and `exports` used to be four copies; a drift between them previously surfaced as "the barrel has it, the types don't". The test walks `lib/*.ts` against all of them. `build-shared.mjs` normalizes its extra names through `packageNameOf`, so subpath specifiers actually match what the manifest declares.
- **New in the build chain: `build-types-check.mjs`.** The chain now fails if any `dist/types` declaration still carries a relative `.ts`/`.mts`/`.cts` specifier — `rewriteRelativeImportExtensions` primarily rewrites JS output, and whether the declaration pass follows has been a per-version behaviour. The current output is clean; the gate exists so a future compiler change cannot quietly regress it.
- **`.gitattributes` keeps `*.bat` and `*.cmd` on CRLF.** cmd.exe parses LF-only batch files unreliably (`goto :label`, parenthesised blocks); the repository currently has none, so this changes nothing today and protects the first one added.
- **The catalog toolchain line moves to the newest the registry has**: `oxlint` 1.89.0, `oxfmt` 0.74.0, `oxlint-tsgolint` 7.0.2005, `rolldown` 1.2.15 and `happy-dom` 21.0.4; every other entry (`vitest` 5.0.5, `@vitest/coverage-v8` 5.0.5, `typescript` 7.0.2, `vite` 8.3.5, `@types/*`, `eslint-plugin-sonarjs`) is already the latest. The bump is rendered from the umbrella root truth and projected by `sync`, lockfiles regenerated per repository. `oxlint` 1.89 tightens two `unicorn` rules; the two hits in this package are mechanical (`String#replaceAll` for the two global-regex rewrites in `lib/canonicalize-region-paths.ts`), and its vitest rule set is unchanged from 1.88's — the snapshot test passing without an edit is the evidence for that claim. The catalog entry for this package stays `^0.1.6` until 0.1.7 is actually on the registry.
- **The vitest rule snapshot test strips `GITHUB_ACTIONS` from the child environment.** oxlint silences `--rules` output entirely under that flag — zero bytes on stdout, exit code 0 — and GitHub Actions injects it into every step, so the snapshot parsed an empty set on all six matrix legs while every local run (the variable absent) stayed green. The parsing subprocess now deletes the variable and forces the colour-off trio, per the repo's standing discipline for judgements that match literals on subprocess output. Reproduced locally by exporting `GITHUB_ACTIONS=true`: the test reddens before the fix and passes after.

## 0.1.5-rc

### Fixed

- **Duplicate `Origin` / `sec-fetch-site` headers are no longer treated as absent** (`lib/trust.ts`). `singleHeader` folded any multi-valued header to `null`, and `null` is read as *absent* on both of those legs — so `sec-fetch-site: same-origin, cross-site` and `Origin: http://evil.test, http://a` both fell through to `trusted`. Reading a tri-state (`absent` / `single` / `duplicate`) fixes the inversion: duplicates now yield `cross-site` and `bad-origin` respectively, and `Host` (which already rejected them explicitly) is folded into the same reader. The previous behaviour was pinned by a test whose stated rationale — *"these two are not the trust source, missing them just falls back to the Host leg"* — holds only from the attacker's side: a client able to duplicate a header could equally omit it, and absent is accepted by design (see the `node:http` local surface). It misses the **infrastructure** side, where a reverse proxy appending an `Origin`, or any upstream that duplicates a header, *downgrades* a request that `sec-fetch-site: cross-site` should have rejected. Header duplication is undecidable, so it is now rejected.
- **IPv4-mapped loopback is loopback on the `Host` leg too** (`lib/trust.ts`). `isLoopbackIPv6` has always classified `::ffff:127.0.0.1` as loopback, so `isNonLoopbackBindHost` reports `false` and the host serves loopback-only — but `isLoopbackHostname` accepted only `::1` and four decimal octets. A browser reaching that address sends `Host: [::ffff:7f00:1]:port` (WHATWG's canonical form), which the old code read as non-loopback: the server **binds, starts, and then 403s every request**. Fail-closed lockout rather than exposure, but a self-inflicted one. Both legs now share `MAPPED_LOOPBACK_PREFIX`, so they cannot drift again. Mapped forms of *non*-loopback addresses (`::ffff:8.8.8.8`) are still rejected.

### Changed

- `resolveLocalePreference` (`lib/locale.ts`) reads `preference` through `Object.hasOwn` instead of a bare index. This is deliberately **opposite** to `fieldOf` in `lib/record.ts`, where the prototype-chain read is load-bearing (cordis service methods are prototype members): this function reads a settings **value**, has no capability-probing use, and with the prototype read a single `Object.prototype.preference = "en"` flipped the UI language of every consuming plugin.

### Not changed, deliberately

- **`os.networkInterfaces()` is still read per request.** Caching it would make the address face unobservable at process scope, and `test/trust-ifaces.test.ts` pins that fallback precisely by swapping a stub table per test. Caching buys one `getifaddrs` on a path that only runs when `servingNonLoopback` is true, and costs a test-only reset hook in production code.
- **A cross-site `GET` with neither `Sec-Fetch-Site` nor `Origin` is still admitted** (browsers below Safari 16.4 / Firefox 90 / Chrome 76). Requiring `Origin` would break every same-origin browser request, since those do not send it. The exposure is bounded: `sendJson` sets no `Access-Control-Allow-Origin`, so SOP blocks the response from being read, and the affected routes are side-effect-free.
- **HTTP/2 is still unguarded.** `:authority` carries no `host` header, so on an `http2` server the `Host` leg is skipped. Unreachable — the host webserver is `node:http` — and there is no Node API to read `:authority` as a `Host` equivalent.

## 0.1.4

### Changed

- **Host line `0.2.1-alpha.1` → `0.2.1-alpha.2`**, in all four places that have to move together: `peerDependencies`, the same seven in `devDependencies`, `engines.dsh` (`>=0.2.1-alpha.2`), and the `overrides` block in `pnpm-workspace.yaml` (86 `dsh-*` pins). Editing only `package.json` is silently reverted by the resolver — the reason that block exists. The cordis half stays: `@deepseek-ai/cordis` `4.0.5-alpha.1`, `@deepseek-ai/cosmokit` `1.8.6-alpha.1`, `@deepseek-ai/schemastery` `3.18.5-alpha.1` and the three cordis plugins are what alpha.2 itself declares (`dsh-tools@0.2.1-alpha.2` peers `cordis: ~4.0.5-alpha.1`), and they match the harness `vendor/` tree byte for byte.
- `dependencies` is still empty, and the install tree still holds **one** copy of every host package: the lockfile resolves 17 distinct `@deepseek-ai/*` names (this package's closure, not the 86 the `overrides` block can pin) and none of them to two versions.
- **Catalog tooling to the current registry heads**: `vitest` and `@vitest/coverage-v8` `5.0.2` → `5.0.3`, `vite` `8.3.1` → `8.3.4`, `rolldown` `1.2.11` → `1.2.13`, `oxlint` `1.86.0` → `1.87.0`, `oxfmt` `0.71.0` → `0.72.0`, `oxlint-tsgolint` `7.0.2003` → `7.0.2004`, `@types/node` `26.6.3` → `26.6.5`, and the two catalog rows this package does not install (`happy-dom` `20.14.6`, `jsdom` `30.1.2`) so a future `catalog:` reference cannot pull a stale one. `typescript` `7.0.2` and `eslint-plugin-sonarjs` `4.2.2` were already at head. `pnpm outdated` is empty after this.
- **`servingNonLoopback`'s documented derivation was wrong for this host, and is now a function.** `@deepseek-ai/dsh-host-webserver`'s `Config.host` went from the two-value union `'127.0.0.1' | '0.0.0.0'` to *any concrete local-interface IP literal*, and a wildcard bind (`0.0.0.0`, `::`, and the mapped forms) is now **rejected at load**. So the line every consumer copied from this package's JSDoc — `webServer.host === "0.0.0.0"` — is constant `false`: the non-loopback service surface changed shape while the test still looked for the literal that can no longer be bound, and a plugin serving a real interface address rejects its own `Host` authority with `403 untrusted host authority` on every LAN request. Fail-closed, so no exposure — but the feature is gone, silently. `./lib/trust` now exports `isNonLoopbackBindHost(webServer.host)` for that derivation.
- `lib/trust.ts`'s header cited "官方那份 `isLoopbackHost`" for the widening it refuses to adopt. That is `@deepseek-ai/dsh-http-proxy`'s (which accepts `::`, `0.0.0.0` and `.localhost`); alpha.2 publishes a **different, same-named** `isLoopbackHost` on `dsh-host-webserver` for the bind side. Both citations are now named by package, because the two do opposite jobs and the short name no longer identifies one of them.

### Added

- **`isNonLoopbackBindHost(host)` in `./lib/trust`**: bind literal → the boolean `TrustOptions.servingNonLoopback` wants. Classifies 127/8, every spelling of `::1` (`::0.0.0.1`, the fully expanded form, `::1%lo`) and IPv4-mapped forms of 127/8 as loopback; everything else that is a literal — interface addresses, link-local with a zone, and the now-unbindable wildcards — as non-loopback. Spelling is folded by WHATWG (`new URL`), not by hand, which is what makes `::0.0.0.1` and `::ffff:127.0.0.1` come out right without an address parser.
- **`@deepseek-ai/dsh-host-webserver` as a devDependency only** — it is not a peer and not a dependency, so the install surface is unchanged. It exists so `test/trust.test.ts` can cross-check `isNonLoopbackBindHost` against the official `isLoopbackHost` over the literal table. `isLoopbackHost`/`isWildcardHost`/`normalizeBindAddress` only became public exports in alpha.2; before that the predicate was module-private, which is why this package had to state the rule in prose instead of checking it.

### Not changed, deliberately

- **No runtime import of the official predicate.** It lives in a host package this package does not otherwise touch; a value import would materialize a second `dsh-host-webserver` in the consumer's profile — the exact class of defect `0.1.3` removed from `dependencies`. The rule is re-implemented from `node:net` + WHATWG instead, and pinned against the official one at *this* package's test time rather than at the consumer's run time.
- **`TrustOptions` keeps the boolean.** Accepting the bind string instead would have been a cleaner API but breaks nine call sites that already pass `servingNonLoopback`, for no change in what the gate decides.
- **Non-literals stay `false`, opposite to the official `!isLoopbackHost`** (which returns `true` for `localhost`, since it only recognizes literals). The host's own config validation rejects non-literals before a plugin ever sees the value; if one arrives anyway, `false` narrows the set of accepted authorities rather than widening it. The divergence is asserted both directions in `test/trust.test.ts` so nobody "aligns" it away.
- **`PTC` `meta` is not surfaced.** alpha.2 adds optional `meta?: JsonValue` to `PtcDispatchEventData`, bringing a sub-call's settlement to parity with native `tool/result` (which has carried `meta` all along). `ToolResultRecord` reads the call-id and the success bit, which is all the gate and the evidence chain branch on; adding a presentation field to the ledger would widen the published type for a consumer that does not exist yet.
- **Nothing else in the consumed surface moved.** Checked against the published declarations, alpha.1 vs alpha.2: `tool/call` and `tool/result` data shapes are byte-identical, `JobStatus`/`JobOutcome`/`ShellProcess` are unchanged (one `JobKindMap` comment and the removal of the `subagent` kind — neither reached here), `LOCALE_IDS` is still `['zh', 'en']`, and `truncateWithoutSplittingSurrogatePair` is unchanged — the only value import this package makes. `SESSION_FORMAT_VERSION` is still 4. Session did grow a `PluginRecord`/`PluginRecordMap`/`appendPluginRecord` vocabulary, but those are explicitly outside `SessionEventMap` and gated to `packages/experimental/`, so `lib/tool-events.ts` sees nothing new.

## 0.1.3

### Changed

- **Breaking (install surface): no `@deepseek-ai/*` left in `dependencies`.** The seven host packages move to `peerDependencies` (`@deepseek-ai/dsh-output-retention` required — it is the one value import, `truncateWithoutSplittingSurrogatePair` behind `truncateEnd`; the six type-only ones optional) plus the same seven in `devDependencies` so this repository still compiles and tests them. `dependencies` is now empty.
  - **Why this was a defect rather than a preference:** a consumer plugin is installed into a profile that runs pnpm with `nodeLinker: hoisted` and `autoInstallPeers: false`. Anything this package listed under `dependencies` was therefore written into the profile as a **real directory**, sitting next to the copy the host process had already loaded. `@deepseek-ai/dsh-tools` keys its `TOOL_RUNTIME_SCHEDULER` with a plain `Symbol` (not `Symbol.for`), so symbol identity is per module instance: the host's `dsh-agent-loop` reads the `ToolRuntime` that was mounted from the duplicate using its own copy's symbol, receives `undefined`, and every native tool call throws `Cannot read properties of undefined (reading 'prepare')` — the entire profile loses its tools. This package's build, typecheck and coverage gate all stayed green right up to that point, which is why the check now lives in `test/publish-manifest.test.ts`.
  - Measured in an isolated profile: installing a consumer that pulls shared `0.1.2` materialises fifteen `@deepseek-ai/*` directories and loads two distinct `dsh-tools` instances in one process; the same consumer against `0.1.3` materialises none and loads one.
  - Consumers that import a type-only facet (`lib/job-outcome`, `lib/tool-events`, `lib/card-apply`, `lib/locale`) keep resolving those host types the way they already do — through their own declarations — because peers are not installed into a profile and optional peers no longer drag a second copy along.
- **`test/publish-manifest.test.ts` gains a manifest-level gate** (`@deepseek-ai/* 一律不进 dependencies`) and the two version-shape assertions now read the peer ∪ dev union instead of `dependencies`. Without the gate the failure is invisible from this repository: the artifact is correct, the host is not.
- `README.md` / `README.zh-CN.md` "Dependencies" rewritten. The previous text justified `dependencies` ("`dsh-output-retention` is a value import, so it must ship as a dependency") — the runtime need is real, the chosen table was not: host-provided runtime packages belong in `peerDependencies`. It also claimed `cordis` uses `~`; the manifest has pinned it exactly since `0.1.2`, and the sentence now says so.

### Not changed, deliberately

- **The exact pins stay exact.** Only the table they live in moves. Loosening them to `^` would let a consumer's host type surface drift to whatever the registry serves, which is the failure `0.1.2` pinned down.
- **`@deepseek-ai/dsh-output-retention` is a required peer, not optional.** It is the only host package reached at runtime; a consumer whose host does not provide it should fail loudly at import rather than get `undefined` two frames inside `truncateEnd`.
- **The release line stays `0.1.x`:** this ships as 0.1.3 rather than 0.2.0, for the reason recorded under 0.1.1 — every sibling pins `^0.1.0`, which under `0.x` resolves to `>=0.1.0 <0.2.0`, so cutting 0.2.0 would need nine coordinated range bumps. Staying on the patch line is exactly what lets every consumer pick this fix up with no edit at all. The cost is that an install-surface change arrives through a patch, as it did in 0.1.1 and 0.1.2.
- **The one consumer-facing failure face is a missing type import.** A package that imported a type-only facet (`lib/job-outcome`, `lib/tool-events`, `lib/card-apply`, `lib/locale`) and relied on shared to drag the host package into its own flat tree must now declare that host package itself. Under pnpm's isolated layout it already had to, because transitive dependencies are not importable there.

## 0.1.2

### Changed

- **Breaking (ledger shape):** `ToolCallRecord.name` is now `string`, and `scanToolEvents` / `toolEventRowsOf` drop a `tool/call` that carries no usable name (missing **or** empty) instead of emitting a row with `name: undefined`. The official type declares `name` required, but the session store cannot enforce it: `Session.append` only runs `snapshotJsonValue`, and the `validateSessionEventData` that follows documents that it "does not validate complete event payloads" and does not cover `tool/call` — measured: `append("tool/call", { arguments: "{}" })` succeeds. `name` is the bucketing key (it is what `editPathOf`, the gate-side `EDIT_TOOLS` list and every refPolicy check branch on), so a call without one cannot be classified. Consumers that read `call.name` as possibly-absent must now handle the call being absent from the row set instead. **The filter lives in the scan layer, not in each consumer** — three sibling packages were carrying three hand-copies of the same guard. `callId` deliberately stays `string | undefined`: it has a real fallback seat (`nc:<seq>`) and its own usability check, and the consumers' `noCallId` bucket wants exactly those rows.
- **Breaking (install surface):** the host dependency line moves onto the alpha channel — every `@deepseek-ai/dsh-*` exact pin `0.2.0-rc.2` → `0.2.1-alpha.1`, `cordis` `~4.0.4` → `4.0.5-alpha.1`, `schemastery` `3.18.4` → `3.18.5-alpha.1`, and the optional peer `@deepseek-ai/dsh` `^0.2.0-rc.2` → `^0.2.1-alpha.1`. **0.1.2 therefore installs only alongside an alpha host**; npm 7+ fails an unsatisfied peer rather than warning about it. The version is bumped in `pnpm-workspace.yaml`'s `overrides` as well as in `package.json` — the overrides block pins the whole `dsh-*` family, so a `package.json`-only edit is silently reverted by the resolver. `@deepseek-ai/dsh-invariants` is dropped from those overrides: it has no alpha release and the runtime invariant plugin is gone.
- **`MessagesCatalog` uses a homomorphic mapped type** (`Record<Locale, { readonly [K in keyof Messages]: string }>`) instead of the previous `Record`-shaped value domain, and `messagesFor` returns that same mapped type. Every consumer in the workspace declares its catalogue as an `interface Messages { readonly x: string }`, and an interface gets no implicit index signature — the intermediate `Record<string, string>` form failed to typecheck in all of them. The mapped type holds for interfaces and type aliases alike, and still rejects a non-string value (`test/type-guards.test.ts` pins both directions).
- The runtime bundle is built with `minify` now. `dist/*.js` drops from 35,020 to 10,345 bytes (−70.5%); `dist/config/oxlint.base.js` from 36,139 to 23,060.

### Fixed

- **`checkCsrf` no longer fails closed on a capitalised header name.** The header name is supplied by the caller (this package deliberately does not unify the siblings' historical names), while Node's `IncomingHttpHeaders` keys are always lower-case. A caller writing the specification-correct `X-Csrf-Token` never matched, so the endpoint returned 403 on every request — a failure whose symptom is far from its cause. Header lookup now folds case; the comparison is untouched, so the token must still match byte for byte and the verdict only moves from "wrongly rejected" to "judged normally".
- **`claimApply` releases its marker when `ctx.effect` throws.** The marker was set to `true` before the effect was registered; if registration failed, nothing would ever reset it and the guard degenerated from "refuse duplicates" into "never applies again" — with a full page reload as the only remedy. The marker is rolled back and the error still propagates.
- `lib/canonicalize-region-paths.ts` claimed it was **not** in `package.json`'s `exports`. It is, and nine sibling packages' `build-*.mjs` import it through that subpath: removing the entry on the strength of that comment would break every one of their builds while this package's own gate stayed green.

### Not changed, deliberately

- **`fieldOf` keeps reading through the prototype chain.** Making it own-property-only is the obvious tidy-up and it would be wrong: consumers use it for capability probes over cordis services, whose methods live on the prototype (`typeof fieldOf(settings, "describe") === "function"` in `quality-gate/host.ts:1267` and `lesson-loop/host.ts:266`; `hasMethods(fieldOf(value, "timer"), ["timeout"])` in `session-rescue/host.ts:502-504`; `typeof fieldOf(session, "snapshotEvents") === "function"` in `session-rescue/host.ts:565`). Switching to `Object.hasOwn` turns all of those to false and makes three packages stop recognising valid services — silently, with no error to trace. The hazard is documented at the declaration instead, so the next reader does not "fix" it.
- **`resolveLocale`'s accepted set stays a literal pair.** Deriving it from the official `LOCALE_IDS` would need a *value* import of a client package on the host half, which the module header already avoids for two other constants. Instead `test/locale.test.ts` asserts that every id in `LOCALE_IDS` is selectable, so the day the host adds a language the gate goes red and someone decides "support it" or "deliberately not" — instead of `resolveLocale` quietly never returning the new id while `MessagesCatalog` forces nine consumers to add a dictionary for it.
- `shrinkJsonlTail` keeps `0` and negative budgets shrinking to ≤ 2 lines, and keeps `NaN` / `+Infinity` returning the input untouched. "0 = never trim" is a trigger policy on the caller (`maxBytes > 0` before the call), not this function's semantics; making it so here would turn that promise into an illusion. The non-finite case is unreachable from both current consumers — one passes a fixed constant, the other normalises to 0 first — so the contract is documented and pinned rather than changed.

### Added

- **`test/dist-size.test.ts`**: a byte budget for the runtime and config bundles (13,000 and 30,000), so a regression that quietly grows the published footprint fails the gate instead of shipping.
- **`test/setup-logs.ts` + `test/log-templates.ts`**: the runtime-log ledger the other five packages in the workspace already had, wired through `setupFiles`. It takes over `console.*`, so the two `console.error` calls in `lib/` neither leak into the test report (each one prints a stack) nor go unclaimed: every `[shared/*]` line must match a template fragment or the run goes red. `trust.test.ts` drops its hand-rolled spy for the ledger. `vitest`'s `silent` is not a substitute — it only hides, and a newly added log would still go unnoticed.
- **Facet ↔ `exports` parity** in `test/publish-manifest.test.ts`, both directions. A new `lib/*.ts` without a subpath is unimportable by every consumer while the build stays green, because the build follows the builder's own `entries` array rather than the manifest; and a subpath left behind after a facet is renamed or merged is an import that throws on arrival. `./lib/canonicalize-region-paths` — in `exports`, out of the barrel, and load-bearing — is pinned by name.
- **A dependency-shape gate**: every `dsh-*` dependency must be pinned exactly (no `^` or `~`), and all of them must match the `dsh` peer's version. The registry's dist-tags are the reason: on `@deepseek-ai/dsh-session`, `latest` points at `0.0.1-rc.1` while the version actually in use is on `next`, so an unpinned `pnpm add` installs something far older than the host ABI. The same-version rule exists because two copies of `dsh-session` in one session make the nominal types (branded ids, projection state) stop recognising each other — and that surfaces at runtime as "unknown callId", never as a type error.

### Tests

- The suite grew from 190 to 226 cases across ten modules, filling gaps in seven directions: **security** (`trust` refuses twelve hostile `Host` glyph forms the file header names but never pinned — `user@` prefix, `%2e`, trailing dot, CRLF injection, IPv6 splicing, out-of-range port; `http` pins `same-site` as cross-origin and the fail-open path for an endpoint that omits `csrf`); **boundary** (byte-exact `readBody` limits on both sides of the `=`, `shrinkJsonlTail`'s equal side and its trailing-newline line count, `truncateEnd` / `truncateStart` at zero, negative, `NaN` and `+Infinity`); **compatibility** (the official `truncateWithoutSplittingSurrogatePair` export still resolves at runtime — `tsc` catches a removed export, not one that is present in the declarations but missing from the JS; a cross-realm `isRecord`); **hidden risk** (a five-thousand-deep cause chain degrades to a placeholder instead of throwing a `RangeError` out of a `catch` block; a hostile `then` getter on a lesson-bus return value; `fieldOf`'s prototype reach); **accuracy** (`jsonl` is trimmed by UTF-8 bytes, not characters); **performance** (ten thousand tool events fold row-for-row with no reordering, and the nameless filter holds at that scale); **function** (`card-apply` had one test for fifty-six lines and now has six, covering flag granularity, the `=== true` occupancy test, marker reset, and the throw path).

## 0.1.1
### Changed

- **Removed `resultIsError`.** It had no consumer: the sibling packages fold tool results through `toolEventRowsOf` / `scanToolEvents`, and `resultRecordOf` reads the success bit directly. Its three tests now go through `toolEventRowsOf`, so the behaviour they pin (message-level `isError`, the retired block-level shape staying a fail-open fingerprint) is still covered.
- `CROSS_ORIGIN_TEXT` is now exported from `./lib/http`. The browser leg of the trust gate wrote its own copy of the same sentence; two literals for one rejection means one of them eventually drifts.
- `scanToolEvents` iterates with `entries()`, and the explicit `event !== undefined` guard is gone: `isRecord` already returns `false` for `undefined` and `null`, so the guard was redundant at runtime and only looked necessary because indexing produced a `| undefined` type.
- `canonicalizeRegionPaths` folds region markers with a single `replace` instead of `split`/`map`/`join`, which no longer builds two intermediate arrays over the whole bundle. `canonicalizeLine` lost its `startsWith` check because the regex already anchors on the line start.
- **`errorText` now returns more text; its name and signature are unchanged.** It went from a single `message` layer to the semantics of the official `@deepseek-ai/dsh-llm` `errorChain`: a cause chain renders as `outer: inner`, an `AggregateError` appends `[e1; e2]`, an empty message falls back to `Error.name`, a cross-realm `Error` yields its own `message` rather than `String()`'s `"Error: ..."`, and a hostile getter or `toString` degrades to a placeholder instead of throwing out. Callers that regex the old text must re-check. The implementation stays local and dependency-free: the official symbol is exported from the `@deepseek-ai/dsh-llm` root, and bundling that root for a browser entry produces 160,105 bytes even with `moduleSideEffects: false` while leaving an unresolvable `node:module` in the artifact. The official client packages themselves never value-import that package.
- `editPathOf` returns a `kind`-discriminated `EditTarget` holding only `write` and `read-view`. `"skip"` was declared but never produced; it only pushed consumers into writing unreachable branches. When no path can be read the matching arm is still returned with `path` set to `undefined`.
- `isCrossOrigin`, `queryParam`, `checkCsrf`, `requestTrust` and `guardTrust` widened their first parameter from `IncomingMessage` to `HttpRequest`, so the partial-request shape the header helpers were written for is now actually usable by callers. `readBody` and `guardBody` still take `IncomingMessage`: they consume the request body and `PartialRequest` does not guarantee async iteration.
- Every field of `ToolCallRecord`, `ToolResultRecord` and `ToolEventRows` is now `readonly`, matching the rest of the package's exported interfaces — a ledger that can be edited in place is no longer evidence.

### Not changed, deliberately

- `callRecordOf` / `resultRecordOf` keep their `let record` + single trailing return. Rewriting them into direct returns is *not* a simplification here: this package runs oxlint with `consistent-return` plus `treatUndefinedAsUnspecified`, which rejects mixing `return undefined` with value returns. The shape exists to satisfy that rule, not for style.
- `parseToolArguments` and `toolArgumentsBad` stay exported. They have no consumer today, but a consumer that folds the ledger itself (`toolEventRowsOf` users) must re-read the arguments fields; without them it would reimplement exactly the field reads this package exists to keep single-sourced.
- The release line stays `0.1.x`: this ships as 0.1.1 rather than 0.2.0. Removing `resultIsError` and changing `editPathOf`'s return shape would normally ask for 0.2.0, but every sibling package pins `^0.1.0`, which under `0.x` resolves to `>=0.1.0 <0.2.0` — cutting 0.2.0 means nine dependency-range bumps have to land in the same release. Staying on 0.1.x avoids that coupling, at the price of these breaking changes arriving through a patch bump; the failure face is a typecheck error on the call site, not a runtime surprise.

### Fixed

- `deriveProjectKey`'s `sep` option selects the **whole** path-semantics arm now; `resolve` follows it instead of staying platform-native. The two were split, so on a Windows runner the POSIX arms folded separators with `/` while `path.resolve` handed back a `D:`-prefixed string: the pinned key literals drifted and one case named a bucket after the entire resolved path (`D:\a\my\proj-…`). Default behaviour is byte-identical on both platforms — POSIX resolves through `path.posix`, Windows through `path.win32`, which is what the platform module is anyway — so no existing bucket moves. Each case now declares which arm it judges, and the realpath stand-in that stripped the cwd prefix `path.resolve` had added (needed only because the arms were split) is gone.
- `sendJson` now serializes before writing headers. Previously a payload `JSON.stringify` rejected on (a circular reference, a `BigInt`) threw *after* `writeHead`, leaving the response open with headers already sent and `end()` never called: the client waited until timeout and the caller could no longer change the status code. The failure is now an ordinary synchronous throw with the response still writable.
- `settleLessonCall` treats function-thenables as awaitable. Missing them left a rejection with no handler, which surfaces as a process-level unhandled rejection — the one failure direction that is unsafe.
- `settleLessonCall` contains a throwing `onFailure` on both failure faces. It previously forked: the synchronous path threw at the caller, the asynchronous path became an unhandled rejection. Both now log and swallow, so the original failure is not masked.
- The trust module no longer cites a stale line number for the official `isTrustedApiRequest`. The cited coordinates pointed at unrelated code; the comment now names the module and symbol and explains the three reasons it cannot be imported (client package, `trustedHosts` is a private field, and the published tarball has no `src/`).

### Added

- `test/publish-manifest.test.ts` now scans the source plane as well as the artifact plane for dates and round-relative wording. The artifact pass cannot see comments, so a cleanup confined to it would be a one-off with no regression protection. Sibling-package identifiers stay forbidden in artifacts only — listing which cards already use a helper is useful documentation.
