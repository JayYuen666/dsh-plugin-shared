# Changelog

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 0.2.2

### Changed

- **The package-wide `syncWrites` option became the file-scoped `syncIoScopes`.** `syncWrites` merged its API names into the single `node/no-sync` setting at the top of the rule table, so registering `writeFileSync` or `rmSync` silenced every synchronous write in the consumer's package — `lib/` and `host.ts` included — while the option's own comment promised a declaration per use. Each `syncIoScopes` entry (`{ files, apis }`) now emits one override, so an exemption is in force only in the files it names. The generated override repeats the baseline read-only list, because oxlint replaces the whole setting for a rule inside an override (measured on oxlint 1.90: an override carrying only `ignores: ["readFileSync"]` made the baseline-exempted `existsSync` report again in that file) — listing only the extra names would hand those files a block of new errors. An entry with empty `files` or empty `apis` throws at load instead of emitting an override that never matches or exempts nothing. Scope overrides sit before a consumer's `extraOverrides`, so a repository can still narrow a named file further. The `node/no-sync` row of `OFF_JUSTIFICATIONS` points at `syncIoScopes`.

### Fixed

- **The install-matrix type probe hands npm one peer spec per argument.** It joined the `@deepseek-ai/*` peers its own declarations reference into a single space-separated string and split that string on whitespace before `npm install`, so a range carrying a union arrived as three arguments and npm answered `ETARGET: No matching version found for undefined@^0.2.2-alpha.2` (measured against the shipped list in a clean directory). The list is now one spec per line and is read line by line, so tokenising no longer depends on how a range is spelled. Union ranges in this manifest stay written without spaces around `||` — the cordis peer is one — so a spec remains a single whitespace-free token for any consumer that splits a spec list on blanks.
- **A clean `npm install` of this package no longer mixes two host lines.** Naming the whole support window in the peer table (`@deepseek-ai/dsh-*` and `engines.dsh` as `^0.2.1-rc.3||^0.2.2-alpha.2`) resolved the install-side complaint it was meant to answer but broke this repository's own install matrix: npm resolves each peer on its own, so the one required peer `@deepseek-ai/dsh-output-retention` landed on `0.2.2-alpha.2` — which requires cordis `~4.0.6-alpha.1` — while cordis resolved to `4.0.5`, the version the `0.2.1-rc.5` plugin group requires, and the install stopped at `ERESOLVE`. Reproduced with npm 11.19.1 against a packed 0.2.2 tarball in an empty directory; the same shape the runner reported. The peer family and `engines.dsh` therefore keep the single `^0.2.1-rc.3`, unchanged from 0.2.1. The declared window does not narrow with it: the host compares `engines.dsh` with `includePrerelease: true`, under which that range is true for `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.1-rc.5` and `0.2.2-alpha.2` (semver 7.8.5, measured) — the second comparator only changed what installers resolve, and what it changed was a conflict.

### Notes

- `exports`, the artifacts and the runtime modules are unchanged; the edit is confined to `./config/oxlint`'s options. Dropping an option is not a patch-level change under strict semver, and it is taken here because that option reaches only the eight repositories in this family, every one of which declares its synchronous exemptions through it: a repository still passing `syncWrites` fails its own typecheck, since `oxlint.config.ts` sits inside each repository's `tsconfig.json` `include`.
- The workspace catalog already names 0.2.2, so a consumer installing on its own — each repository's CI, and the workspace's `verify:published` — resolves this package from the registry and fails `ERR_PNPM_PACKAGE_NOT_FOUND` until 0.2.2 is published; `sync --check` reports the same range as unsatisfiable. Publishing first is also what makes the option change safe to consume: against an installed 0.2.1 a `syncIoScopes` declaration is an unknown option, so the files it names keep no exemption and start reporting `node/no-sync`.

## 0.1.9

This section is one fix to the build module shipped in 0.1.8.

### Fixed

- **`collapseStorePaths` now collapses the `// ` module-banner form, not only `//#region` lines** (`lib/build-client.ts`). When this package is installed from the registry, rolldown annotates the inlined dependency modules with `// node_modules/.pnpm/<name>@<version>_<peer-suffix>/node_modules/...` banners; the region-only rewrite left those untouched, and the whole-output leftover check then failed the consumer's client build on every clean install — the same steps a repository's CI runs (`pnpm install --frozen-lockfile` → `prepare`) and the workspace's `verify:published` rehearsal runs. A workspace-link install never produces a `.pnpm` segment, which is why every local check kept passing through the 0.1.8 release. The rewrite now recognises both comment forms — `//#region` markers and `// ` banners, each keeping its own prefix — after backslash normalisation and with the same `../`-prefix allowance; the leftover check is unchanged, and an occurrence on a non-comment line still fails the build. Verified by re-running a consumer's client build inside a preserved registry-shaped install tree with the patched module: the build passes and the banners come out as `// node_modules/@jayyuen66/dsh-plugin-shared/dist/...` in registry installs and the same rewrite with `// ../dsh-plugin-shared/dist/...` relative banners in workspace-link installs — what is stable across install layouts is the rewrite, not the banner bytes themselves.

The main item is the build-orchestration unification: the four new subpaths below absorb the build logic that the plugin repositories used to carry as diverging near-copies in their root `build-*.mjs` scripts, and the seven JavaScript plugin repositories move to thin configuration layers in the same round. - **The license holder line reads `JayYuen666` (2026)**, aligned with the rest of the family.
- **The host development line is `0.2.1-rc.3`** (`@deepseek-ai/dsh` peer, `engines.dsh`, and the matching development pins) — the release line the family upgraded to in the same round.
- **Consumers' declared floor rises only after this version is on the registry.** Until then the workspace's import check reports the seven consumers as failing, and a fresh workspace install loses the workspace link to this package (the consumers lock the exact published floor, and a local 0.1.8 does not satisfy `0.1.7`). ## 0.1.7

0.1.6 is still the newest version on the registry, and this section covers everything in the working tree since it. Two groups of changes landed here: the delivery machinery around the package (workflow files, README, catalog floor — the first twelve entries below), and a review round that touched the library and the baseline configs themselves. `exports` is unchanged — no subpath was added, removed or renamed — but `lib/` and `config/` are not byte-identical to 0.1.6, so consumers that read fields on malicious objects, call `claimApply` flags, or lean on the vitest/oxlint baselines should read the entries below before moving. The eight consumers in this family were updated in the same round and their full checks pass against this tree.

### Changed

- **Every third-party action in the four workflow files is locked to a commit SHA** with the resolved version in the trailing comment (`actions/checkout`, `pnpm/action-setup`, `actions/setup-node`, `actions/upload-artifact`, `actions/download-artifact`, `actions/attest`, `actions/dependency-review-action`, `github/codeql-action`, `ossf/scorecard-action`). A tag can be moved by its owner; a workflow whose only job is to judge whether a change is safe must not itself be re-pointable. `actionlint` no longer comes from a mutable container tag either — the CI step downloads the upstream release tarball, checks it against a fixed SHA-256, and only then runs it.
- **Concurrency groups carry the event name** (`${{ github.workflow }}-${{ github.event_name }}-${{ github.ref }}`), and cancellation is limited to `push` and `pull_request`. The weekly upstream-check run and a push to `main` share `refs/heads/main`; grouping by ref alone let a push cancel the weekly run, which is the only signal for "did the host line move". The comment above the block in both `ci.yml` and `codeql.yml` records this.
- **The coverage upload runs under `if: always()`.** Uploading only on success meant the one artifact worth reading — the report from the run that failed — was the one never published. `if-no-files-found` is `warn`, not `error`: under `always()` the directory is absent whenever typecheck, lint or build fails first, and failing here would report a missing path over the real error and abort the remaining steps.
- **The run summary is the last step of the check job.** `${{ job.status }}` is evaluated when that step runs, so any judging step after it left the summary asserting `success` while the job went on to fail — a single conclusion that is wrong rather than merely absent.
- **The build-provenance attestation is a separate job**, conditional on `github.event_name != 'pull_request'`. `id-token` and `attestations` are job-level permissions: attaching them to the install job would hand a forked pull request the write capability regardless of any step-level `if`. The separate job declares `contents: read` + `id-token: write` + `attestations: write` + `artifact-metadata: write`, which is the full set the upstream action documents.
- **The install job holds `contents: read` only.** It runs `pnpm pack` and `npm install`, which execute `prepack` and dependency install scripts from the pull request's own tree; a token reachable from that tree is a token an installer script can read.
- **Every `actions/checkout` passes `persist-credentials: false`.** Nothing in these workflows runs a git write verb, while the steps after the checkout do run the repository's own install, build and test scripts — leaving the token in `.git/config` widened what those scripts could reach for no benefit.
- **The publish workflow never lets its npm credential leave the step that reads it.** The secret is masked with `::add-mask::` and used in place by each of the two steps that need it — the registry pre-check and the publish step — rather than being handed on through a step output. A step output is materialised as a file under the runner's temporary directory, and every later step in the same job can enumerate and read it, which leaves the reachability problem that the job environment had: `pnpm install --frozen-lockfile` and `pnpm run check` run code from the repository and its dependencies. What crosses steps now is one boolean — whether the pre-check found a usable static token. The publish step exports `NODE_AUTH_TOKEN` only when that boolean is true and the value is non-empty: exporting an empty string would fill the `${NODE_AUTH_TOKEN}` placeholder that `setup-node` writes into the npm config with nothing, so an OIDC-only run would go on to authenticate with an empty credential. The token check exits `0` when the secret is absent, so publishing over OIDC (the path the registry records as `GitHub Actions <npm-oidc-no-reply@github.com>`) is not blocked by it.
- **The publish job has `timeout-minutes: 45`** and keeps `concurrency: publish` with `cancel-in-progress: false`. Without the timeout a stuck install or check consumes the runner's default time limit with no signal; without the concurrency group two dispatches race on the same version.
- **`.github/dependabot.yml` no longer has an npm update block.** Catalog truth lives in the workspace root, and every other literal version in this manifest is locked by `pnpm-workspace.yaml`'s `overrides` — a Dependabot bump of those would be resolved back to the locked value, so the pull request would merge without changing the installed tree. The action block stays, and its groups now cover `github/codeql-action*` and `ossf/scorecard-action*`, which the previous patterns missed.
- **New README section: the shared version floor** (`README.md` / `README.zh-CN.md`). A consumer profile can lock this package with a pnpm `overrides` entry; locking it below the version that introduced a `./lib/...` subpath installs a copy without the names the consumer imports at run time, and the host then reports `N entries did not activate` with `does not provide an export named ...` — the package installs, never loads, and no per-repository CI run can see it. The section points readers at `exports` and this file before locking.
- **`catalog` for `@jayyuen66/dsh-plugin-shared` moves `^0.1.5` → `^0.1.6`**, the newest version the registry actually has; the previous floor named a version below the current one.
- **`config/vitest.base.ts` splits coverage overrides out of `test`.** The trailing `...test` spread let a consumer that only wanted to change one `coverage` reporter replace the whole block — the four-way 100 % thresholds and the exclusion list included — with nothing failing anywhere. Coverage overrides now go through a dedicated `coverage` option merged key by key, and `thresholds` itself is merged key by key, so relaxing one metric cannot delete the other three; `test.coverage` is rejected at load with a message pointing at the new option. `coverage.include` comes only from `coverageInclude` — the override option's shape has no `include` key at all, so the measured file set stays single-sourced. Test discovery widens to `test/**/*.{test,spec}.{ts,tsx,mts,cts}` (a pure superset; no current file in any consumer matches the added patterns), the coverage exclusion list gains `**/*.d.ts`, `**/test/**` and `**/node_modules/**`, and an empty or whitespace `coverageInclude` throws at load instead of silently measuring nothing while the thresholds keep passing.
- **`config/oxlint.base.ts` narrows the sonarjs fallback and exports the vitest rule snapshot.** The fallback now only skips resolution when the caller's own plugin entry actually resolves sonarjs; previously any caller-supplied `jsPlugins` entry silenced the failure, which resurfaced later as oxlint's own `Plugin 'sonarjs' not found` with none of the actionable message. `VITEST_ALL_RULES` is exported and a consistency test compares it against `oxlint --rules` at the installed version, so an upstream rule addition or removal fails the check instead of silently widening what the off-list covers. The case/spec file patterns are single-sourced, and the note that claimed `no-await-in-loop` was relaxed for scripts is corrected — that rule is on for both sides.
- **`lib/canonicalize-region-paths.ts` gains an exact-prefix mode: `canonicalizeRegionPaths(code, pkgDir, cwd?)`.** With `cwd` the two strippable prefixes are computed as `rel(cwd, pkgDir)` and `rel(cwd, parent(pkgDir))` instead of guessed by segment name, so a package-internal directory that happens to share the parent directory's — or the package's — name is no longer stripped away, and the result is the same bytes from any build directory. All twenty build call sites across the family pass `process.cwd()`. The two-argument form is unchanged. One shape has no lossless fix in a pure-string pass and is documented in the module header instead: a package-internal directory named after the package itself, built with cwd exactly the package's parent, produces canonical text that a re-run would strip once more. A shape guard also keeps multi-line template literals whose content happens to begin a line with `//#region ` out of rewriting scope.
- **`lib/card-apply.ts` claims with a per-call symbol and restores what was there before.** The placeholder under the flag key is a fresh symbol per claim; cleanup removes it only when the key still holds that token and restores the previous property descriptor (or deletes the own property when there was none). A late disposer from a previous context can therefore neither clear a newer instance's flag — which used to let a third apply re-mount — nor leave a stale `true` blocking the next one. Flags are validated at load: an empty string or an `Object.prototype` member name throws instead of silently disabling the protection.
- **`lib/record.ts` reads never throw, and `Object.prototype` is not a service.** `fieldOf` and `hasMethods` are the capability checks consumers run against values from `ctx.get(...)`; a malicious getter or Proxy trap now yields `undefined` instead of letting its throw escape the check — `hasMethods({}, ["toString"])` and friends return `false`. Methods on classes and intermediate prototypes are still recognized; only the members that live on `Object.prototype` itself are refused.
- **`lib/errors.ts` follows from that: `isSettingsConflict`'s try/catch was dead code and is gone** — the never-throw guarantee now lives in `fieldOf` and is stated there. `errorText` also stops treating an owned empty string as "read a message": it falls through to `String(error)`, same reason as the empty-`message` fallback below it.
- **`lib/text.ts` treats sub-code-unit budgets as no budget at all.** `0 < minChars < 1`, NaN and non-positive values return the empty string — the same answer as `truncateEnd(text, 0)` — instead of `slice(-0.5)`'s whole string, which was exactly the truncation this function exists to enforce.
- **`lib/lesson-bus.ts` no longer leaks an async `onFailure` rejection, and settling failures no longer recurse.** `report()` now catches a rejection thrown asynchronously by an `onFailure` handler; the cleanup path that hides its own failures keeps its rejections to a log line instead of handing them back to `onFailure` — the failure came from the settling itself, so reporting it through the same channel would recurse.
- **`lib/card-diff.ts` compares by form semantics instead of `JSON.stringify`.** `null`, `undefined` and an absent key stay equal; objects compare key set plus every value, arrays length plus every element, and the leaves go through `Object.is` — so `NaN` equals `NaN`, `-0` does not equal `0`, and key order no longer decides equality.
- **`lib/project-key.ts` recognizes UNC share roots.** `\\server\share` — with or without the `\\?\` long-path prefix and the trailing backslash — is a root, not a two-segment relative path misclassified as one.
- **`lib/job-outcome.ts` handles the `kill()` promise and records `exitCode: null` completions as 0.** The official handle's `kill` returns `Promise<boolean>`; a synchronous try/catch only caught the throwing form, so a rejected promise escaped to the process-level unhandledRejection counter from a cleanup branch. `jobOutcomeOf` also writes `exit code: 0` when a completed process reports no exit code, matching the host's own `processOutcome` reading; consumers that project `proc.exitCode` are unaffected.
- **`lib/jsonl.ts` removes the whole leading blank run after a split, CRLF included.** The old `slice(1)` removed a single `\n` and never matched a `\r\n`-leading remainder, so a split landing inside a blank run could re-emit it.
- **`build-host.mjs` exports `facets`, and a consistency test now fixes all four hand-maintained lists.** The barrel member list, the `dist/index.d.ts` module list, the tsconfig include and `exports` used to be four copies; an inconsistency between them previously surfaced as "the barrel has it, the types don't". The test walks `lib/*.ts` against all of them. `build-shared.mjs` normalizes its extra names through `packageNameOf`, so subpath specifiers actually match what the manifest declares.
- **New in the build chain: `build-types-check.mjs`.** The chain now fails if any `dist/types` declaration still carries a relative `.ts`/`.mts`/`.cts` specifier — `rewriteRelativeImportExtensions` primarily rewrites JS output, and whether the declaration pass follows has been a per-version behaviour. The current output is clean; the check exists so a future compiler change cannot quietly regress it.
- **`.gitattributes` keeps `*.bat` and `*.cmd` on CRLF.** cmd.exe parses LF-only batch files unreliably (`goto :label`, parenthesised blocks); the repository currently has none, so this changes nothing today and protects the first one added.
- **The catalog toolchain line moves to the newest the registry has**: `oxlint` 1.89.0, `oxfmt` 0.74.0, `oxlint-tsgolint` 7.0.2005, `rolldown` 1.2.15 and `happy-dom` 21.0.4; every other entry (`vitest` 5.0.5, `@vitest/coverage-v8` 5.0.5, `typescript` 7.0.2, `vite` 8.3.5, `@types/*`, `eslint-plugin-sonarjs`) is already the latest. The bump is rendered from the workspace root truth and projected by `sync`, lockfiles regenerated per repository. `oxlint` 1.89 tightens two `unicorn` rules; the two hits in this package are mechanical (`String#replaceAll` for the two global-regex rewrites in `lib/canonicalize-region-paths.ts`), and its vitest rule set is unchanged from 1.88's — the snapshot test passing without an edit is the evidence for that claim. The catalog entry for this package stays `^0.1.6` until 0.1.7 is actually on the registry.
- **The vitest rule snapshot test strips `GITHUB_ACTIONS` from the child environment.** oxlint silences `--rules` output entirely under that flag — zero bytes on stdout, exit code 0 — and GitHub Actions injects it into every step, so the snapshot parsed an empty set on all six matrix legs while every local run (the variable absent) kept passing. The parsing subprocess now deletes the variable and forces the colour-off trio, per the repo's standing discipline for checks that match literals on subprocess output. Reproduced locally by exporting `GITHUB_ACTIONS=true`: the test fails before the fix and passes after.

### How this release was verified

`pnpm run check` passes: typecheck, `oxlint`, both builds, vitest at 100 % on all four coverage metrics, `oxfmt --check`. ## 0.1.5-rc

### Fixed

- **Duplicate `Origin` / `sec-fetch-site` headers are no longer treated as absent** (`lib/trust.ts`). `singleHeader` reduced any multi-valued header to `null`, and `null` is read as *absent* on both of those legs — so `sec-fetch-site: same-origin, cross-site` and `Origin: http://evil.test, http://a` both fell through to `trusted`. Reading a tri-state (`absent` / `single` / `duplicate`) fixes the inversion: duplicates now yield `cross-site` and `bad-origin` respectively, and `Host` (which already rejected them explicitly) is merged into the same reader. The previous behaviour was asserted by a test whose stated rationale — *"these two are not the trust source, missing them just falls back to the Host leg"* — holds only from the attacker's side: a client able to duplicate a header could equally omit it, and absent is accepted by design (see the local `node:http` API). It misses the **infrastructure** side, where a reverse proxy appending an `Origin`, or any upstream that duplicates a header, *downgrades* a request that `sec-fetch-site: cross-site` should have rejected. Header duplication is undecidable, so it is now rejected.
- **IPv4-mapped loopback is loopback on the `Host` leg too** (`lib/trust.ts`). `isLoopbackIPv6` has always classified `::ffff:127.0.0.1` as loopback, so `isNonLoopbackBindHost` reports `false` and the host serves loopback-only — but `isLoopbackHostname` accepted only `::1` and four decimal octets. A browser reaching that address sends `Host: [::ffff:7f00:1]:port` (WHATWG's canonical form), which the old code read as non-loopback: the server **binds, starts, and then 403s every request**. Fail-closed lockout rather than exposure, but a self-inflicted one. Both legs now share `MAPPED_LOOPBACK_PREFIX`, so they cannot diverge again. Mapped forms of *non*-loopback addresses (`::ffff:8.8.8.8`) are still rejected.

### Changed

- `resolveLocalePreference` (`lib/locale.ts`) reads `preference` through `Object.hasOwn` instead of a bare index. This is deliberately **opposite** to `fieldOf` in `lib/record.ts`, where the prototype-chain read is essential (cordis service methods are prototype members): this function reads a settings **value**, has no capability-checking use, and with the prototype read a single `Object.prototype.preference = "en"` flipped the UI language of every consuming plugin.

### Not changed, deliberately

- **`os.networkInterfaces()` is still read per request.** Caching it would make the address list unobservable at process scope, and `test/trust-ifaces.test.ts` fixes that fallback precisely by swapping a stub table per test. Caching saves one `getifaddrs` on a path that only runs when `servingNonLoopback` is true, and costs a test-only reset hook in production code.
- **A cross-site `GET` with neither `Sec-Fetch-Site` nor `Origin` is still admitted** (browsers below Safari 16.4 / Firefox 90 / Chrome 76). Requiring `Origin` would break every same-origin browser request, since those do not send it. The exposure is bounded: `sendJson` sets no `Access-Control-Allow-Origin`, so SOP blocks the response from being read, and the affected routes are side-effect-free.
- **HTTP/2 is still unguarded.** `:authority` carries no `host` header, so on an `http2` server the `Host` leg is skipped. Unreachable — the host webserver is `node:http` — and there is no Node API to read `:authority` as a `Host` equivalent.

It is, and nine sibling packages' `build-*.mjs` import it through that subpath: removing the entry on the strength of that comment would break every one of their builds while this package's own checks kept passing.

### Not changed, deliberately

- **`fieldOf` keeps reading through the prototype chain.** Making it own-property-only is the obvious tidy-up and it would be wrong: consumers use it for capability checks over cordis services, whose methods live on the prototype (`typeof fieldOf(settings, "describe") === "function"` in `quality-gate/host.ts:1267` and `lesson-loop/host.ts:266`; `hasMethods(fieldOf(value, "timer"), ["timeout"])` in `session-rescue/host.ts:502-504`; `typeof fieldOf(session, "snapshotEvents") === "function"` in `session-rescue/host.ts:565`). Switching to `Object.hasOwn` turns all of those to false and makes three packages stop recognising valid services — silently, with no error to trace. The hazard is documented at the declaration instead, so the next reader does not "fix" it.
- **`resolveLocale`'s accepted set stays a literal pair.** Deriving it from the official `LOCALE_IDS` would need a *value* import of a client package on the host side, which the module header already avoids for two other constants. Instead `test/locale.test.ts` asserts that every id in `LOCALE_IDS` is selectable, so the day the host adds a language the check fails and someone decides "support it" or "deliberately not" — instead of `resolveLocale` quietly never returning the new id while `MessagesCatalog` forces nine consumers to add a dictionary for it.
- `shrinkJsonlTail` keeps `0` and negative budgets shrinking to ≤ 2 lines, and keeps `NaN` / `+Infinity` returning the input untouched. "0 = never trim" is a trigger policy on the caller (`maxBytes > 0` before the call), not this function's semantics; making it so here would turn that promise into an illusion. The non-finite case is unreachable from both current consumers — one passes a fixed constant, the other normalises to 0 first — so the behavior is documented and asserted by a test rather than changed.

### Added

- **`test/dist-size.test.ts`**: a byte budget for the runtime and config bundles (13,000 and 30,000), so a regression that quietly grows the published footprint fails the check instead of shipping.
- **`test/setup-logs.ts` + `test/log-templates.ts`**: the runtime-log record list the other five packages in the workspace already had, wired through `setupFiles`. It takes over `console.*`, so the two `console.error` calls in `lib/` neither leak into the test report (each one prints a stack) nor go unaccounted for: every `[shared/*]` line must match a template fragment or the run fails. `trust.test.ts` drops its hand-rolled spy for the record list. `vitest`'s `silent` is not a substitute — it only hides, and a newly added log would still go unnoticed.
- **Module ↔ `exports` parity** in `test/publish-manifest.test.ts`, both directions. A new `lib/*.ts` without a subpath is unimportable by every consumer while the build keeps passing, because the build follows the builder's own `entries` array rather than the manifest; and a subpath left behind after a module is renamed or merged is an import that throws on arrival. `./lib/canonicalize-region-paths` — in `exports`, out of the barrel, and essential — is asserted by name.
- **A dependency-shape check**: every `dsh-*` dependency must be locked exactly (no `^` or `~`), and all of them must match the `dsh` peer's version. The registry's dist-tags are the reason: on `@deepseek-ai/dsh-session`, `latest` points at `0.0.1-rc.1` while the version actually in use is on `next`, so an unlocked `pnpm add` installs something far older than the host ABI. The same-version rule exists because two copies of `dsh-session` in one session make the nominal types (branded ids, projection state) stop recognising each other — and that surfaces at runtime as "unknown callId", never as a type error.

### Tests

- The suite grew from 190 to 226 cases across ten modules, filling gaps in seven directions: **security** (`trust` refuses twelve malicious `Host` glyph forms the file header names but never fixed — `user@` prefix, `%2e`, trailing dot, CRLF injection, IPv6 splicing, out-of-range port; `http` asserts `same-site` as cross-origin and the fail-open path for an endpoint that omits `csrf`); **boundary** (byte-exact `readBody` limits on both sides of the `=`, `shrinkJsonlTail`'s equal side and its trailing-newline line count, `truncateEnd` / `truncateStart` at zero, negative, `NaN` and `+Infinity`); **compatibility** (the official `truncateWithoutSplittingSurrogatePair` export still resolves at runtime — `tsc` catches a removed export, not one that is present in the declarations but missing from the JS; a cross-realm `isRecord`); **hidden risk** (a five-thousand-deep cause chain falls back to a placeholder instead of throwing a `RangeError` out of a `catch` block; a malicious `then` getter on a lesson-bus return value; `fieldOf`'s prototype reach); **accuracy** (`jsonl` is trimmed by UTF-8 bytes, not characters); **performance** (ten thousand tool events keep their row order with no reordering, and the nameless filter holds at that scale); **function** (`card-apply` had one test for fifty-six lines and now has six, covering flag granularity, the `=== true` occupancy test, marker reset, and the throw path).

## 0.1.1
### Changed

- **Removed `resultIsError`.** It had no consumer: the sibling packages process tool results through `toolEventRowsOf` / `scanToolEvents`, and `resultRecordOf` reads the success bit directly. Its three tests now go through `toolEventRowsOf`, so the behaviour they assert (message-level `isError`, the retired block-level shape staying a fail-open fingerprint) is still covered.
- `CROSS_ORIGIN_TEXT` is now exported from `./lib/http`. The browser side of the trust checks wrote its own copy of the same sentence; two literals for one rejection means one of them eventually diverges.
- `scanToolEvents` iterates with `entries()`, and the explicit `event !== undefined` guard is gone: `isRecord` already returns `false` for `undefined` and `null`, so the guard was redundant at runtime and only looked necessary because indexing produced a `| undefined` type.
- `canonicalizeRegionPaths` rewrites region markers with a single `replace` instead of `split`/`map`/`join`, which no longer builds two intermediate arrays over the whole bundle. `canonicalizeLine` lost its `startsWith` check because the regex already anchors on the line start.
- **`errorText` now returns more text; its name and signature are unchanged.** It went from a single `message` layer to the semantics of the official `@deepseek-ai/dsh-llm` `errorChain`: a cause chain renders as `outer: inner`, an `AggregateError` appends `[e1; e2]`, an empty message falls back to `Error.name`, a cross-realm `Error` yields its own `message` rather than `String()`'s `"Error: ..."`, and a malicious getter or `toString` renders as a placeholder instead of throwing out. Callers that regex the old text must re-check. The implementation stays local and dependency-free: the official symbol is exported from the `@deepseek-ai/dsh-llm` root, and bundling that root for a browser entry produces 160,105 bytes even with `moduleSideEffects: false` while leaving an unresolvable `node:module` in the artifact. The official client packages themselves never value-import that package.
- `editPathOf` returns a `kind`-discriminated `EditTarget` holding only `write` and `read-view`. `"skip"` was declared but never produced; it only pushed consumers into writing unreachable branches. When no path can be read the matching arm is still returned with `path` set to `undefined`.
- `isCrossOrigin`, `queryParam`, `checkCsrf`, `requestTrust` and `guardTrust` widened their first parameter from `IncomingMessage` to `HttpRequest`, so the partial-request shape the header helpers were written for is now actually usable by callers. `readBody` and `guardBody` still take `IncomingMessage`: they consume the request body and `PartialRequest` does not guarantee async iteration.
- Every field of `ToolCallRecord`, `ToolResultRecord` and `ToolEventRows` is now `readonly`, matching the rest of the package's exported interfaces — records that can be edited in place are no longer evidence.

### Not changed, deliberately

- `callRecordOf` / `resultRecordOf` keep their `let record` + single trailing return. Rewriting them into direct returns is *not* a simplification here: this package runs oxlint with `consistent-return` plus `treatUndefinedAsUnspecified`, which rejects mixing `return undefined` with value returns. The shape exists to satisfy that rule, not for style.
- `parseToolArguments` and `toolArgumentsBad` stay exported. They have no consumer today, but a consumer that builds the records itself (`toolEventRowsOf` users) must re-read the arguments fields; without them it would reimplement exactly the field reads this package exists to keep single-sourced.
- The release line stays `0.1.x`: this ships as 0.1.1 rather than 0.2.0. Removing `resultIsError` and changing `editPathOf`'s return shape would normally ask for 0.2.0, but every sibling package locks `^0.1.0`, which under `0.x` resolves to `>=0.1.0 <0.2.0` — cutting 0.2.0 means nine dependency-range bumps have to land in the same release. Staying on 0.1.x avoids that coupling, at the price of these breaking changes arriving through a patch bump; the failure is a typecheck error on the call site, not a runtime surprise.

### Fixed

- `deriveProjectKey`'s `sep` option selects the **whole** path-semantics arm now; `resolve` follows it instead of staying platform-native. The two were split, so on a Windows runner the POSIX arms joined separators with `/` while `path.resolve` handed back a `D:`-prefixed string: the asserted key literals drifted and one case named a key after the entire resolved path (`D:\a\my\proj-…`). Default behaviour is byte-identical on both platforms — POSIX resolves through `path.posix`, Windows through `path.win32`, which is what the platform module is anyway — so no existing key moves. Each case now declares which arm it judges, and the realpath stand-in that stripped the cwd prefix `path.resolve` had added (needed only because the arms were split) is gone.
- `sendJson` now serializes before writing headers. Previously a payload `JSON.stringify` rejected on (a circular reference, a `BigInt`) threw *after* `writeHead`, leaving the response open with headers already sent and `end()` never called: the client waited until timeout and the caller could no longer change the status code. The failure is now an ordinary synchronous throw with the response still writable.
- `settleLessonCall` treats function-thenables as awaitable. Missing them left a rejection with no handler, which surfaces as a process-level unhandled rejection — the one failure direction that is unsafe.
- `settleLessonCall` contains a throwing `onFailure` on both failure paths. It previously split into two behaviors: the synchronous path threw at the caller, the asynchronous path became an unhandled rejection. Both now log the error and stop it there, so the original failure is not masked.
- The trust module no longer cites a stale line number for the official `isTrustedApiRequest`. The cited coordinates pointed at unrelated code; the comment now names the module and symbol and explains the three reasons it cannot be imported (client package, `trustedHosts` is a private field, and the published tarball has no `src/`).

The artifact pass cannot see comments, so a cleanup confined to it would be a one-off with no regression protection. Sibling-package identifiers stay forbidden in artifacts only — listing which cards already use a helper is useful documentation.
